A memory store keeps the original turn and everything derived from it, so scoring retrieval means deciding which stored form is allowed to earn credit. TIAP holds the saved ranked output fixed and changes only that.

TIAP the scoring target problem

The same run, three verdicts
nDCG more than triples from Raw to Canonical on identical saved output. A paper reporting one of these numbers is reporting a choice.
And the rows are not comparable
Canonical covers only 332 of the 470 queries, because not every turn produces a serving memory. Comparing it against the other two unrestricted would confound the target with query difficulty, which is why TIAP falls back to the shared subset.
Across the bundle
83.4 to 94.0% of shared queries change nDCG under a target switch, over 16 saved runs spanning two benchmarks, four retrievers, a parser density sweep, and the Mem0 and MemoryOS transfers.
